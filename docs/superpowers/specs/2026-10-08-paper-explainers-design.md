## 1. 目标

把论文里难懂的原理和数学讲清楚,让人再去读原文时能看懂。

- 新增「图解」板块:每篇论文一个讲解页,用动画、交互图、彩色公式、真实数据回放把原理讲明白。
  它是读原文前的引路,**不替代原文**。
- 整站换一套新视觉,更好看、图和动画更多。
- 现有 40 篇中英对照原文**一字不动地保留**。

**成功标准**:没有相关背景的读者,5–10 分钟看完一篇图解,能用自己的话讲清
「它做了什么、每个设计为什么这样」;图解里没有任何一句跟原文矛盾。

## 2. 已确认的决策

| 维度 | 决策 | 来源 |
|---|---|---|
| 动图用途 | 网页内交互动画 + 导出 GIF / MP4 给站外用(README、公众号、视频号) | user 选「两种都要」 |
| 语言 | 先中文;文案按 key 存数据文件,以后加英文只加一份翻译 | user 选 |
| 搭建方式 | 骨架统一(五问结构 + 文案数据 + 共享引擎),核心交互图每篇单独做 | user 选方案 1 |
| 画风 | 不限手绘;按论文内容选。流程用矢量线条,比喻用插画,数据用精确图表 | user 补充 |
| 视频 | 不是每篇都要;只在「动起来才讲得清」的地方导出 | user 补充 |
| AI 插画 | 可以装 ComfyUI,作为可选手段 | user 补充 |
| Manim 视频 | 方案 1 里的可选手段,给数学多的论文用,不作为主线 | 方案讨论 |

**被否掉的方案**:
- 全模板化(每篇一份 JSON + 通用组件):加论文快,但通用组件讲不了具体机制,
  会变成带动画的幻灯片。
- 视频优先(Manim):数学效果好,但不能交互、改一处要重新渲染。

## 3. 整站结构和视觉

### 3.1 页面结构

| 页面 | 内容 |
|---|---|
| 首页 | 开场动画:「AI 工程栈」分层图逐层画出,点哪层跳哪个主题;「图解系列」精选区(带小动图);按主题分的论文目录 |
| 主题页 | 论文卡片;有图解的卡片带「有图解」标记和小动图 |
| 论文页 · 原文视图 | 现有中英对照内容不动;新增左侧目录、阅读进度条;顶部「图解 / 原文」切换 |
| 论文页 · 图解视图 | 新;每节末尾「对照原文 →」跳到原文对应小节 |

**链接**:原文保持 `docs/{zh,en}/articles/<slug>.html`(旧链接不失效);
图解新增 `docs/zh/explain/<slug>.html`。英文侧暂不出图解,入口显示「中文版」并链过去。

### 3.2 视觉方向

- **底色**:暖纸色(比现有 `#faf9f5` 稍暖);新增深色模式(深墨蓝底)。
- **字体**:标题粗无衬线;长文正文衬线;讲解页批注和手写标签用霞鹜文楷(开源手写感楷体)。
- **颜色只管意思**:每个主题一个颜色(沿用现有主题色);图里的颜色意思全站固定:
  保留 / 变好 = 绿,丢弃 = 灰,崩溃 / 警告 = 红,重点 = 橙。
- **画风按内容选**:统一的只有颜色意思和字体。
- **动效**:首页开场、卡片悬停、滚动到位才出现。`prefers-reduced-motion` 时一律显示最终画面,内容不缺。

### 3.3 样张先行

视觉方向光靠文字没法判断。第一阶段只做样张(新首页首屏 + 图解场景 4),
user 看过再铺全站;风格不对只返工样张。

## 4. 图解页骨架(所有论文通用)

按「技术解释五问」排章节(来源:`~/.claude/rules/conduct.md`「技术解释五问」):

1. 这是什么(本质定义)
2. 没有它会怎样
3. 为什么这么设计(每个设计带「去掉它会怎样」开关)
4. 用在什么场景
5. 机制细节(放最后;篇幅不够时砍这一章,不砍前四章)

前面加开场,后面加「边界」和「自测 3 题」。顶部五问章节导航,可直接跳。

### 4.1 出处标记(全页规则)

| 标记 | 含义 | 要求 |
|---|---|---|
| 原文 | README / 论文 / 源码里写着的 | 点开显示原句 + 文件 + 位置;`check_sources.py` 逐字核对 |
| 解读 | 我们推出来的 | 写明从什么推的 |
| 示意 | 演示用的假设数字 | 不能当真实数据 |

### 4.2 表现手段(每篇挑合适的)

| 手段 | 适合 |
|---|---|
| 交互图解(滑块、开关) | 取舍、「不这样会怎样」 |
| 彩色公式(公式项与图部件联动高亮) | 数学 |
| 分步动画(播放 / 单步 / 拖进度) | 算法流程 |
| 真实数据回放 | 实验结果 |
| AI 插画(ComfyUI) | 场景、比喻、开场 |
| Manim 视频 | 数学推导多的论文 |
| GIF / MP4 | 站外分享 |
| 自测题 | 检查是否真懂 |

## 6. 技术实现

### 6.1 目录

```
docs/assets/theme.css            新视觉,替换 anthropic.css + site.css
docs/assets/explain/
  engine.js                      滚动推进;动画 = 「时间 t → 帧」纯函数;__seek(t) 供导出
  formula.js                     彩色公式(KaTeX)+ 与 SVG 部件联动
  source.js                      原文 / 解读 / 示意 标记与弹出原句
  quiz.js                        自测题
docs/assets/vendor/              第三方库固定版本入库(KaTeX 等)
docs/zh/explain/<slug>.html      构建产物
explain-src/<slug>/
  zh.json                        文案、出处、自测题(以后加 en.json)
  widgets/                       本篇专用交互图,一个场景一个文件
  sources/                       原始材料副本 + 来源 commit
  illustrations/                 ComfyUI 工作流、提示词、种子
tools/                           导出、读数、检查脚本
```

- `docs/scripts/build.py` 扩展图解页模板;文字在构建时写进 HTML,不开 JS 也完整。
- 不引入前端框架;原生 ES module。

### 6.2 动画为什么写成「t → 帧」

导出 GIF 时可精确跳到任意帧截图,不靠实时录屏(录屏掉帧、每次结果不同)。
同一套函数既给网页播放,也给导出用。

### 6.3 GIF / MP4 导出

- Playwright 打开 `?capture=<场景>`:隐藏导航,固定画布(16:9,1200×675),逐帧 `__seek(t)` 截图。
- ffmpeg(本机 `/opt/homebrew/bin/ffmpeg`)合成:GIF 用调色板两遍法;MP4 用 H.264。
- 体积上限:GIF ≤ 4MB,MP4 ≤ 15MB。
- MP4 字幕由页面在 capture 模式下绘制,和网页文案同一份数据。
- Playwright 作为 `tools/package.json` 的开发依赖,不进 `docs/`。

### 6.4 `progress.png` 读数

- `tools/digitize_progress.py`:按颜色识别绿点(保留)与灰点(丢弃),按坐标轴刻度换算数值,输出 `progress.json`(含估计误差)。
- 自检:绿点数必须 = 15(图标题)。
- 页面上写明 karpathy 画图时过滤过数据:崩溃不画,比基线差超过 0.0005 不画
  (`analysis.ipynb`:`below = valid[valid["val_bpb"] <= baseline_bpb + 0.0005]`),
  所以图上灰点少于 83 − 15。
- 绿点旁的文字标签照图转录;原图里被截断的(如 `depth 9 aspect_ratio 57 (same dim 512 + ex...`)保留截断并注明。

### 6.5 ComfyUI

- 装在 `~/ComfyUI`(仓库外),MPS 后端。
- 模型在 24GB 内存上实测出图质量和耗时后再定。
- 插画里不放文字;文字由网页叠加。
- 工作流 JSON、提示词、种子入库,图片转 WebP。
- 效果不行时退回代码画的 SVG 插画。失败方向是「看得见」(图难看),不会悄悄出错。
